# ศูนย์บัญชีและเงื่อนไข

ไอคอน 👥 ผู้ใช้และเงื่อนไข กับ 🛡️ ผู้ดูแลระบบ เปิดหน้าศูนย์บัญชีเดียวกันคนละหมวด เฉพาะ administrator โดยมีบทบาทและสิทธิ์ตรวจที่ API ด้วย

- ค้นหาจากชื่อ อีเมล UUID แท็ก และชื่อที่แสดง กรองบัญชีเปิดอยู่ ระงับ และหมดอายุ
- ดูอีเมล/สถานะยืนยันอีเมล วันสร้าง บทบาท และสิทธิ์ โดยไม่ส่ง password hash, refresh token หรือแม่แบบเสียงให้หน้าจัดการ
- แก้ชื่อที่แสดงใน **หน้าจัดการ** แท็ก และบันทึกภายใน ชื่อนี้ไม่ได้เขียนทับชื่อใน Voice Identity หรือชื่อเข้าสู่ระบบ อีเมลยืนยันยังเป็นข้อมูลอ่านอย่างเดียว
- แก้เงื่อนไขระงับบัญชี วันหมดสิทธิ์ และวันในสัปดาห์ตาม Asia/Bangkok ระบุอย่างน้อยหนึ่งวัน เงื่อนไขตรวจจริงที่ login/refresh และคำขอ HTTP ที่ยืนยันตัวตน ส่วน Gemini Live ตรวจตอนเริ่มและตรวจซ้ำทุก 30 วินาที การเปลี่ยนบทบาท/สิทธิ์ทำให้ปิด Live เดิมภายในรอบตรวจ
- แต่ละการแก้เงื่อนไขมี revision ป้องกันการเขียนทับ พร้อม audit ก่อน/หลัง ผู้ดำเนินการ และเวลา ประวัติการแก้บทบาท/สิทธิ์ผ่านหน้าศูนย์บัญชีนี้เก็บใน audit ของศูนย์บัญชีด้วย
- บทบาท administrator/operator และสิทธิ์ chat, sentinel:command, settings, system:read เป็นรายการที่ระบบรองรับ ไม่รันโค้ดหรือคำสั่งจากบันทึก/แท็ก
- ต้องยืนยันชื่อเข้าสู่ระบบก่อนเปลี่ยนสิทธิ์ ป้องกันการลดบทบาท/ถอด settings ของตนเองและผู้ดูแลคนสุดท้ายตาม AuthService เดิม ไม่อนุญาตเงื่อนไขระงับ/หมดอายุ/จำกัดวันกับบัญชีที่มีบทบาท administrator และไม่ให้เพิ่มบทบาท administrator ให้บัญชีที่มีเงื่อนไขจำกัดอยู่ ต้องล้างเงื่อนไขก่อน
- สร้างบัญชีเจ้าหน้าที่ administrator/operator ผ่านฟอร์ม รหัสผ่านเริ่มต้นไม่ถูกบันทึกใน audit และเคลียร์เมื่อส่งคำขอเสร็จ ผู้ใช้ทั่วไปสมัครด้วยอีเมล OTP + Voice Identity เดิม ไม่มีการส่งอีเมลเชิญหรือรหัสผ่านให้อัตโนมัติ
- เปลี่ยนรหัสผ่านและเพิกถอนเซสชันทุกอุปกรณ์โดยยืนยันชื่อบัญชีก่อน รหัสผ่านเคลียร์จากฟอร์มเมื่อคำขอเสร็จและไม่อยู่ใน Audit ใช้ credential version ปฏิเสธ access token เดิมในคำขอใหม่และปิด Live เดิมในรอบตรวจ แม้ JWT ยังไม่หมดอายุ
- เปิดศูนย์ความปลอดภัยเพื่อดู/จัดการเซสชันและเหตุการณ์ ส่วนสิทธิ์แพ็กเกจ/โควตาอยู่ศูนย์การเงิน ไม่เปิดแพ็กเกจโดยแก้สิทธิ์ผู้ใช้

ข้อจำกัด: ไม่มีการแก้อีเมลข้ามขั้นตอนยืนยัน ไม่ลบไฟล์/เสียงหรือปิดบัญชีถาวรจากหน้านี้ ไม่ได้เพิ่มระบบกู้คืนข้อมูลหรือ mass delete เงื่อนไขนี้เป็นการควบคุมบัญชีที่ลงทะเบียน ไม่ควบคุม guest session ชั่วคราวที่ยังไม่มีบัญชี ฟังก์ชันพื้นหลังที่เริ่มทำงานไว้แล้วอาจต้องมีการยกเลิกงานแยกต่างหาก รายการบัญชียังโหลดทั้งหมดตาม AuthRepository เดิม ไม่ใช่ pagination ฝั่งเซิร์ฟเวอร์

ก่อน main: ทดสอบสอง URL บน staging ทั้งบทบาทจริง การบันทึกเงื่อนไข และยืนยันผู้ใช้ที่ระงับถูกปฏิเสธ API/Live ตามรอบตรวจ ปัจจุบันข้อความและแท็กเป็นข้อมูล ไม่ใช่กฎ executable
