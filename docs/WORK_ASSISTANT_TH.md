# ผู้ช่วยงาน Panthorium

เปิดจาก Start > **ผู้ช่วยงาน** หรือพูด “เปิดผู้ช่วยงาน” ผู้ใช้ต้องเข้าสู่ระบบและมีสิทธิ์ `chat` ข้อมูลทุกคำขอผูกกับบัญชีที่เซิร์ฟเวอร์ยืนยัน ไม่มีการเลือกเจ้าของข้อมูลจาก request body

## กระบวนการใช้งาน

1. สร้างแฟ้มงาน ตั้งชื่อลูกค้าหรือโครงการ เลือกไฟล์เดิมหรืออัปโหลดไฟล์ และวางข้อความประกอบ
2. เลือกสรุป ถามจากข้อมูล ร่างเอกสาร ปรับภาษา แปล หรือเสนอรายการงาน
3. ตรวจร่างกับตำแหน่งต้นทางที่แสดง แก้ร่าง แล้วสร้าง Word, Excel หรือ PowerPoint
4. เปิดตัวแก้ไข Office เดิมเพื่อจัดข้อความ ตาราง สูตรหรือสไลด์ต่อ ดาวน์โหลดไฟล์จริง หรือเปิด `.print.html` เพื่อพิมพ์/บันทึก PDF ผ่านเบราว์เซอร์
5. ตรวจรายการงาน ผู้รับผิดชอบ และวันเวลา ก่อนยืนยันสร้างนัดในปฏิทินและเลือกการเตือนทางอีเมล

การสร้างไฟล์จากร่างที่ผู้ใช้ตรวจแล้วเป็นการแปลงแบบกำหนดแน่นอน ไม่เรียก AI มาเขียนร่างใหม่ Excel ต้องมีตารางจริงในร่าง การส่งออกคงชื่อและข้อความ ตัวเลขธรรมดาถูกเก็บเป็นตัวเลข ส่วนค่าคล้ายสูตรจากข้อความไม่กลายเป็นสูตรที่ทำงานเอง

## ขอบเขตเอกสารและ AI

- PDF ที่มีข้อความ, DOCX, XLSX, PPTX และข้อความ UTF-8: TXT/CSV/TSV/Markdown/JSON
- ไม่เกิน 6 ไฟล์ ไฟล์ละ 6 MiB; PDF ไม่เกิน 100 หน้า ข้อความที่สกัดได้ไม่เกิน 80,000 ตัวอักษรต่อไฟล์ และบริบทจากไฟล์รวมไม่เกิน 48,000 ตัวอักษร ข้อความที่ผู้ใช้วางเพิ่มไม่เกิน 16,000 ตัวอักษร
- ไม่มี OCR หรือการอ่านรูป/กราฟที่ฝังอยู่ในเอกสาร PDF สแกนต้องแปลงเป็นข้อความก่อน
- ตำแหน่งอ้างอิงมาจากหน้าของ PDF, ย่อหน้าของ Word, ชีต/เซลล์ของ Excel หรือสไลด์ของ PowerPoint ย่อหน้า Word ไม่ถูกอ้างเป็นเลขหน้าที่อาจเปลี่ยนเมื่อจัดหน้า
- สูตร Excel ที่รองรับคำนวณด้วยตัวประเมิน Office เดิม สูตรที่คำนวณไม่ได้แสดงเป็นข้อมูลที่ยังไม่ทราบ ไม่ใช้ cache เดิมเป็นผลปัจจุบัน
- ตำแหน่งอ้างอิงที่ไม่มีในชุดต้นทางถูกปฏิเสธ คำตอบที่ไม่มีตำแหน่งอ้างอิงแสดงให้ตรวจต้นฉบับ การมีตำแหน่งอ้างอิงไม่ได้รับรองว่าการตีความทุกประโยคถูกต้อง
- ข้อเสนอรายการงานจาก AI ยังไม่สร้างนัดหรืออีเมล ไม่มีการเดากำหนดส่งให้ผู้ใช้ หาก provider ส่งข้อความแทนข้อมูลรายการ ระบบแสดงข้อความให้ตรวจและเพิ่มรายการด้วยตนเอง
- ใช้ AI gateway และการคิดโควตาเดิม การเข้าถึง local AI ยังคงเป็นไปตามนโยบายเดิม

## การเก็บงานและการกู้คืน

- PostgreSQL `panthorium_work_projects` เก็บตาม `owner_id`; ไม่เกิน 40 แฟ้มต่อบัญชี แฟ้มละ 300,000 ไบต์ เก็บร่างก่อนหน้า 6 ฉบับ งาน 50 รายการ และประวัติส่งออก 30 งาน
- การบันทึกตรวจ version เพื่อกันสองหน้าต่างเขียนทับกัน เมื่อชนกันจะเก็บร่างบนหน้าจอและให้โหลดฉบับบนระบบหรือเก็บเป็นแฟ้มใหม่
- ร่างที่ยังไม่ซิงก์เก็บใน localStorage แยกบัญชีและแฟ้มงานเมื่อเปิดตัวเลือกกู้คืนบนอุปกรณ์ หมดอายุหลัง 24 ชั่วโมง และลบเมื่อออกจากระบบ/สลับบัญชี ผู้ใช้ปิดตัวเลือกนี้ได้ ร่างที่บันทึกบนระบบยังอยู่
- ไฟล์ต้นฉบับและไฟล์ Office ที่สร้างอยู่ใน Cloud Files ของบัญชีเดิม ใช้โควตาพื้นที่และดาวน์โหลดเดิม แฟ้มงานไม่มีสิทธิ์เปิดไฟล์ของบัญชีอื่น
- ขั้นตอนส่งออก/ลบบัญชีที่เจ้าหน้าที่ดำเนินการต้องรวม `panthorium_work_projects WHERE owner_id = ...`, รายการ `panthorium_agent_memories` และ `panthorium_reminders` ของบัญชีนั้น พร้อม Cloud Files ตามกระบวนการเดิม

## รายการงาน ปฏิทิน และการเตือนที่ผูกกัน

รายการงานที่สร้างจากผู้ช่วยงานมี calendar event ที่ระบุ `source=work-assistant:<projectId>` และอาจมีอีเมลเตือน การสร้าง เลื่อนกำหนด เปลี่ยนชื่อ ทำเสร็จ หรือยกเลิกใช้ transaction เดียวครอบคลุมแฟ้มงาน ปฏิทิน และ email outbox

การเลื่อน/ลบรายการเหล่านี้ผ่านปฏิทินหรือคำสั่งเสียงเดิมส่งกลับเข้ากระบวนการเดียวกัน การเตือนที่ยัง `scheduled` จึงปรับตามหรือยกเลิกพร้อมกัน หากเริ่มส่งแล้วหรือผลส่งไม่แน่นอน ระบบไม่รับการเปลี่ยนแปลงที่อาจทำให้ส่งซ้ำ

กำหนดส่งของงานนี้เป็นวันเวลาจุดเดียว ไม่มีนัดซ้ำ ช่วงเวลา สถานที่ หรือคำเชิญผู้เข้าร่วม ชื่อผู้รับผิดชอบเป็นป้ายกำกับเท่านั้น การเตือนส่งถึงอีเมลที่ยืนยันแล้วของบัญชีผู้ใช้ตามความยินยอม ไม่ส่งถึงบุคคลในช่องผู้รับผิดชอบ นัดและการเตือนเดิมที่สร้างแยกกันนอกผู้ช่วยงานยังไม่ถูกจับคู่ให้อัตโนมัติ

## คำสั่งเสียงและการอนุมัติ

`work.read` อ่านแฟ้มงานหรือข้อความต้นทาง ส่วน `work.save`, `work.draft`, `work.export` และ `work.task` ใช้ action ledger เดิม ผู้ใช้เห็นข้อมูลที่ขอเปลี่ยนและยืนยัน payload ที่ตรึงไว้ รวมเลขฉบับงาน กำหนดเวลา และการรับอีเมล คำสั่งที่ AI สร้างเองไม่ใช่การอนุมัติ

ตัวอย่าง: “เปิดผู้ช่วยงาน”, “สรุปไฟล์ในแฟ้มงานนี้”, “แปลร่างนี้เป็นภาษาอังกฤษ”, “สร้าง Word จากร่างนี้”, “เลื่อนงานส่งข้อเสนอเป็นวันที่ ... เวลา ...” กด **สั่งด้วยเสียง** ในแฟ้มงานเพื่อส่งบริบทของแฟ้มที่เลือกเข้าสู่เสียงเดิม

## ตรวจสอบก่อนเผยแพร่

- `npm run check:work` และ `npm run test:work`: ไฟล์จริง การอ้างอิง การแยกบัญชี ประวัติร่าง ข้อขัดแย้งการบันทึก ไฟล์ Office การยืนยัน และการย้อนคืนเมื่อเขียนปฏิทินไม่สำเร็จ
- `TEST_DATABASE_URL=... node test/work-assistant-postgres.js`: PostgreSQL จริง การย้อนคืนหลายตาราง การแก้พร้อมกัน และการแยกเจ้าของข้อมูล
- `node test/work-assistant-browser.js`: Chromium ผ่าน HTTP router จริง ตั้งแต่ upload PDF ถึงดาวน์โหลด DOCX เปิดตัวแก้ไขและตั้งงาน ทดสอบขนาดจอ desktop/phone โดยใช้ AI/email fixtures
- การตอบจาก provider จริง ไมโครโฟนจริง และการส่งอีเมลจริงต้องมีหลักฐานทดสอบแยกจากชุด fixture ข้างต้น ไม่ถือว่าผ่านเพียงเพราะมี provider configuration
