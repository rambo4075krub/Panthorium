# สร้างสรรค์และเอกสาร — ปลั๊กอินรวมของ Panthorium

Sentinel AI และเมนู Start ใช้บริการสร้างงานชุดเดียวกัน ผู้ใช้สั่งผ่านข้อความ เสียง
หรือเปิดเครื่องมือโดยตรงได้ ผลงานเก็บใน Cloud Files ของบัญชีผู้ใช้ และใช้ file ID
ส่งต่อไปยังเครื่องมืออื่นโดยไม่ต้องดาวน์โหลดแล้วอัปโหลดซ้ำ

## เครื่องมือ

| เมนู | Plugin ID | ผลลัพธ์ |
| --- | --- | --- |
| รูปภาพ | `image` | PNG/JPEG/WebP จาก Vertex Gemini image |
| วิดีโอ | `video` | MP4 จาก Video Studio/Veo เดิม รองรับภาพตั้งต้น PNG/JPEG หนึ่งภาพ |
| เอกสาร | `document` | DOCX แก้ไขได้ และ HTML จัดหน้าสำหรับพิมพ์ |
| ตาราง | `spreadsheet` | XLSX พร้อมชนิดตัวเลข/ข้อความ และ HTML สำหรับพิมพ์ |
| งานนำเสนอ | `presentation` | PPTX แก้ไขได้ และ HTML สำหรับพิมพ์ |

หน้าต่างใช้ระบบหน้าต่างเดิมของ Panthorium มีแท็บทั้งห้าประเภท ประวัติงาน
การเลือกไฟล์ต้นทาง ดาวน์โหลดผลงาน และปุ่มส่งต่อไปยังเครื่องมืออื่น
หมวด Start ใหม่ชื่อ **สร้างสรรค์และเอกสาร** ใช้รูปแบบกลุ่มย่อยพับ/ขยายเดิม

## การสั่ง Sentinel

ตัวอย่างคำสั่ง:

- “สร้างภาพสินค้าโทนส้ม แล้วนำภาพไปทำสไลด์แนะนำสินค้า”
- “สร้างภาพป่าลอยฟ้า แล้วทำเป็นวิดีโอเคลื่อนไหว 8 วินาที”
- “อ่านไฟล์ยอดขายของฉัน แล้วทำรายงานพร้อมตารางสำหรับพิมพ์”
- “สร้างงานนำเสนอภาษาไทยจากเอกสารที่เลือก”

Sentinel เรียก `studio.catalog` เพื่อตรวจความพร้อม แล้วเสนอ `studio.create`
พร้อมรายละเอียดงาน ขั้นตอน และไฟล์ต้นทาง ระบบอนุมัติเดิมของ Panthorium
ผูกคำขอกับ action ID และ hash ของรายละเอียด ผู้ใช้ตรวจรายละเอียดก่อนเริ่มทำงาน
โมเดลไม่สามารถอนุมัติตัวเองด้วย `confirmed` หรือเปลี่ยนเจ้าของงานได้
ช่องเสียงใช้การอนุมัติ Live เดิม ช่องพิมพ์แสดงบัตรตรวจงานในหน้าสตูดิโอ

`studio.jobs` และ `studio.status` อ่านสถานะจริงเท่านั้น ไม่ทำงานซ้ำ
สถานะ “อยู่ในคิว” หรือ “กำลังทำงาน” ไม่ใช่การยืนยันว่าไฟล์สร้างเสร็จแล้ว

## การเชื่อมเครื่องมือ

หนึ่ง workflow มีได้ไม่เกิน 5 ขั้นตอน แต่ละขั้นตอนประกาศชนิดงาน คำสั่ง
file IDs และ `usePrevious` เพื่อรับผลงานขั้นก่อนหน้า การประมวลผลเป็นลำดับ:

1. ตรวจบัญชี สิทธิ์ รูปแบบข้อมูล และ Auto/Never ทุกขั้นตอนก่อนรับงาน
2. บันทึกงานและ idempotency key ลง PostgreSQL
3. ล็อกงานด้วย lease เพื่อให้หลาย Cloud Run instances ไม่ทำขั้นตอนเดียวกันซ้ำ
4. ตรวจสิทธิ์ล่าสุดและสิทธิ์ในไฟล์ก่อนเรียกปลั๊กอิน
5. บันทึกผลงานใน Cloud Files แล้วบันทึก file IDs และแหล่งที่มา
6. ส่งต่อเฉพาะไฟล์ที่เข้ากันได้และผู้ใช้มีสิทธิ์อ่าน

งานที่เสร็จแล้วในขั้นก่อนหน้ายังคงปรากฏ หากขั้นถัดไปผิดพลาด
ขั้นที่เหลือจะถูกระงับ งานที่อาจส่งถึงผู้ให้บริการแล้วแต่ไม่ได้รับผลยืนยัน
จะแสดง `needs_review` เพื่อหลีกเลี่ยงการส่งคำขอที่เสียเงินซ้ำโดยอัตโนมัติ

## สถานะและโหมด

| ค่า | ความหมาย |
| --- | --- |
| `queued` | บันทึกงานแล้ว รอขั้นตอนถัดไป |
| `running` | กำลังประมวลผล หรือรอผลจากผู้ให้บริการ |
| `completed` | สร้างและบันทึกผลงานครบแล้ว |
| `failed` | มีข้อผิดพลาดที่รายงานได้ |
| `needs_review` | ผลการส่งงานไม่แน่ชัด ต้องตรวจสอบก่อนเริ่มงานใหม่ |
| `auto` | อนุญาตให้ปลั๊กอินทำงานตามคำขอที่อนุมัติแล้ว |
| `never` | ปิดการเรียกปลั๊กอินจากหน้าสตูดิโอและ Sentinel |

Auto ไม่ยกเลิกการตรวจบัญชีหรือข้ามการอนุมัติ การตั้ง Never ของวิดีโอ
ครอบคลุมเส้นทางสร้างวิดีโอเดิมของ Media Studio และ MCP ด้วย
การเปลี่ยนโหมดไม่สามารถย้อนคืนค่าบริการของงานที่ส่งถึงผู้ให้บริการไปแล้ว

## API และองค์ประกอบ

| API | หน้าที่ |
| --- | --- |
| `GET /api/studio/catalog` | รายการปลั๊กอิน ความพร้อม และโหมด |
| `POST /api/studio/jobs` | รับงาน/เวิร์กโฟลว์และทำขั้นตอนแรกแบบจำกัดขอบเขต |
| `GET /api/studio/jobs` | ประวัติงานของบัญชีปัจจุบัน |
| `GET /api/studio/jobs/:id` | อ่านสถานะโดยไม่มีผลข้างเคียง |
| `POST /api/studio/jobs/:id/advance` | ทำขั้นตอนถัดไป/ตรวจงานผู้ให้บริการ |
| `PUT /api/studio/plugins/:id/mode` | บันทึก Auto/Never ของบัญชี |

- `CreativeStudioService`: รายการปลั๊กอิน ตรวจข้อมูล นโยบาย และการส่งต่องาน
- `CreativeStudioRepository`: งานและโหมดใน PostgreSQL; memory ใช้เฉพาะ dev/test ที่เปิดชัดเจน
- `OfficeArtifactService`: สร้าง Office Open XML จริงและฉบับสำหรับพิมพ์
- `registerCreativeStudioTools`: เชื่อมกับ ToolRegistry และระบบอนุมัติเดิม
- `creative-studio-ui.js`: หน้าต่างและเมนูร่วมสำหรับทุกเครื่องมือ

ปลั๊กอินรุ่นนี้เป็นความสามารถภายในที่ลงทะเบียนด้วยโค้ด ไม่มีการดาวน์โหลด
หรือรันโค้ดปลั๊กอินภายนอกที่ผู้ใช้ส่งมา การเพิ่มปลั๊กอินใหม่ต้องเพิ่ม adapter
การตรวจ input/output และสิทธิ์ในรายการที่ระบบยอมรับ

## การทำงานเมื่อปิดเบราว์เซอร์

งานและ provider operation handle เก็บใน PostgreSQL โดยไม่มีการเปิดโมเดล inference
ค้าง 24 ชั่วโมง การเดินงานต่อใช้ `POST /internal/jobs/tick` ที่ตรวจ Google OIDC
และรวม `creativeStudio.tick()` กับ scheduler เดิม ฝั่งหน้าจอเรียก advance ได้เมื่อเปิดอยู่

ต้องมี Cloud Scheduler จริง รวมทั้ง `SCHEDULER_OIDC_AUDIENCE` และ
`SCHEDULER_SERVICE_ACCOUNTS` จึงจะเดินขั้นตอนต่อได้เมื่อไม่มีผู้เปิดหน้าจอ
ตรวจการตั้งค่าด้วย `scripts/configure-cloud-scheduler.sh` และทดสอบ authenticated tick
การบันทึกงานสำเร็จหรือหน้า health สีเขียวอย่างเดียวไม่ยืนยันความพร้อมส่วนนี้
รักษา Cloud Run min instances เป็น 0 และไม่เปิด interval fallback ใน production

## เงื่อนไขและขอบเขตรุ่นแรก

- ต้องมีบัญชีที่มีสิทธิ์ `chat`, PostgreSQL, Cloud Files และผู้ให้บริการที่ตั้งค่าถูกต้อง
- ความพร้อมจาก catalog หมายถึงตรวจการตั้งค่าแล้ว ยังไม่ใช่ผลทดสอบเรียกโมเดลจริง
- รูปภาพใช้ `PANTHORIUM_IMAGE_MODEL` และ `SENTINEL_IMAGE_LOCATION`; วิดีโอใช้ค่าของ Video Studio เดิม
- งานวิดีโอ 4/6/8 วินาที และอัตราส่วน 16:9 หรือ 9:16; ขนาดผลงานอยู่ภายใต้โควตา Cloud Files เดิม
- ต่อบัญชีรับไม่เกิน 30 งานต่อวัน รวมขั้นตอนสร้างภาพ/วิดีโอไม่เกิน 10 ขั้นตอนต่อวัน และมีงานค้างได้ไม่เกิน 2 งาน นับวันตามเวลาไทย; งานที่ผลไม่แน่ชัดยังนับเพื่อป้องกันค่าใช้จ่ายซ้ำ
- เนื้อหาเอกสารและสไลด์ที่ AI ร่างควรตรวจความถูกต้องก่อนใช้จริง
- XLSX รุ่นนี้จัดเก็บข้อมูลและตัวเลข; ข้อความที่ขึ้นต้นด้วย `=` ไม่ถูกแปลงเป็นสูตรที่รันได้
- ถ้า AI ส่งกลับเฉพาะร้อยแก้วโดยไม่มีข้อมูลตาราง ปลั๊กอินตารางจะแจ้งให้เพิ่มข้อมูลตาราง
- HTML สำหรับพิมพ์เปิดในเบราว์เซอร์แล้วเลือก Print หรือ Save as PDF ได้ ไม่มีการส่งคำสั่งไปยังเครื่องพิมพ์โดยไม่ถาม
- ไฟล์อยู่ในขอบเขตบัญชีส่วนตัว การแบ่งปันระหว่างสมาชิกองค์กรต้องผ่านระบบสิทธิ์องค์กรแยกต่างหาก
- การทดสอบอัตโนมัติใช้ผู้ให้บริการจำลอง ตรวจรูปแบบคำขอและไฟล์จริงได้ แต่ไม่ยืนยัน IAM/เครดิต/การสร้างสื่อจริงใน staging

## ก่อนส่ง production

รัน `npm run check:studio`, `npm run test:studio`, ชุดทดสอบเดิม และ CI PostgreSQL
deploy staging แล้วรัน `STUDIO_SMOKE_URL=... node test/creative-studio-deployed.js`
ซึ่งตรวจทั้ง `/` และ `/admin`, ไฟล์ UI ตรงกับ commit และ API ส่วนตัวต้องล็อกอิน
หลังจากนั้นตรวจบัญชีผู้ใช้จริง: เปิดทั้งห้าเครื่องมือ สั่งผ่านข้อความ/เสียง สร้างงานจริง
เปิดไฟล์ Office พิมพ์ภาษาไทย ส่งต่องาน ทดสอบ Never และเปิดหน้าจอใหม่เพื่อดูประวัติ
ก่อนนำ main ให้ใช้ขั้นตอน acceptance ใน `docs/STAGING.md`
