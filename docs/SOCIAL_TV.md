# Social Media: Feed, Watch และ TV

ปรับปรุง 26 ตุลาคม 2026

ลำดับเมนู: Feed → Short → Watch → Live → TV → Market → Community → Chat → Connect → Profile → Friends → ปุ่ม ↻

Feed ใช้โพสต์ภาพและข้อความ; Short ใช้คลิปสั้นแบบเดิม; Watch ใช้วิดีโอยาวและภาพยนตร์ โดยแนบไฟล์จาก Cloud ตามโควตาเดิม หรือใส่ลิงก์ YouTube / MP4 / WebM / HLS ที่มีสิทธิ์เผยแพร่ ไม่เปลี่ยนขนาดไฟล์สูงสุดของระบบ Cloud และไม่จัดหาเนื้อหาภาพยนตร์ให้เอง

โพสต์เก่า kind `watch` และ Community สาธารณะยังใช้ ID ความคิดเห็น ไลก์ และสิทธิ์เดิม: ภาพ/ข้อความอยู่ใน Feed วิดีโอเก่าอยู่ใน Short วิดีโอยาวใหม่ใช้ kind `video` กับ module `watch` จึงไม่ต้องย้ายหรือลบฐานข้อมูล ส่วน Chat คง API/record ของ Talk เดิมและรองรับชื่อเดิมเป็น alias

## TV สำหรับผู้ชม

| ปุ่ม | การทำงาน |
| --- | --- |
| ค้นหา | ค้นชื่อช่อง ผู้ให้บริการ หมายเลข และหมวดรายการ |
| ช่องทั้งหมด / ผู้ให้บริการ | ดูช่องที่เผยแพร่แล้ว หรือเลือกสถานี |
| ชมสดที่เว็บไซต์สถานี | เปิดหน้าชมสดทางการในแท็บใหม่ |
| เล่นใน Panthorium | เล่นสัญญาณที่ผ่านการตรวจสอบ; หยุดโหลดเมื่อเปลี่ยนหน้า/ปิดหน้าต่าง |
| ผังรายการ | เปิดผังจากผู้ให้บริการ ไม่คาดเดารายการที่ออกอากาศอยู่ |
| เพิ่มช่องโปรด / ช่องโปรด | บันทึกช่องโปรดในบัญชี ใช้ข้ามอุปกรณ์ได้ |
| เพิ่มช่อง TV / ช่องของฉัน | ส่งข้อมูลช่องใหม่ ตรวจสถานะ แก้ไข หรือลบช่องของตน |

รายการตั้งต้นเป็นลิงก์ทางการ Thai PBS, 7HD และ PPTV ไม่ใช่การรับรองสิทธิ์นำสัญญาณสถานีเหล่านี้มาเผยแพร่ซ้ำ และไม่ได้ดึง URL สัญญาณที่ซ่อนในหน้าเว็บ

## วิธีเพิ่มช่องสำหรับผู้ให้บริการ

1. เข้าบัญชี Panthorium → Social Media → TV → เพิ่มช่อง TV
2. ใส่ชื่อช่อง ผู้ให้บริการ หมายเลข/หมวด เว็บไซต์ชมสด และผังรายการถ้ามี
3. เลือกรูปแบบการรับชม:
   - เว็บไซต์สถานี: ใช้หน้าชมสดทางการ; เหมาะกับผู้ให้บริการที่ต้องล็อกอิน สมัครสมาชิก หรือใช้ DRM
   - YouTube: ใช้ URL วิดีโอ/Live ที่เจ้าของเปิดให้ฝัง ต้องเป็น video ID ของรายการ ไม่ใช่ URL หน้าช่อง
   - HLS: ผู้ให้บริการส่ง HTTPS `.m3u8` ที่อนุญาตให้ใช้ พร้อม CORS สำหรับ manifest, segments และทรัพยากรที่เกี่ยวข้อง รูปแบบเสียง/วิดีโอต้องรองรับโดยเบราว์เซอร์
   - MP4/WebM: ใช้ URL ไฟล์ HTTPS ที่อนุญาตให้เล่นภายนอก
4. กรอกช่องทางติดต่อสำหรับผู้ดูแล ยืนยันสิทธิ์ และใช้ปุ่มทดสอบการรับชม
5. กดส่งช่องให้ตรวจสอบ ผู้ดูแลที่มี `administrator` และ `settings` เปิดปุ่มตรวจสอบช่อง ตรวจสอบผู้ให้บริการ/สิทธิ์ด้วยตนเอง ทดสอบสัญญาณ แล้วอนุมัติหรือไม่อนุมัติพร้อมหมายเหตุ

ช่องใหม่และช่องที่แก้ไขเป็น pending จนกว่าจะอนุมัติ ข้อมูลติดต่อและบันทึกการตรวจสอบไม่แสดงต่อผู้ชมทั่วไป การยืนยันสิทธิ์ด้วย checkbox ไม่ใช่การยืนยันตัวตนหรือการอนุญาตจากสถานีอัตโนมัติ ระบบไม่ใช้ API แบบเสียเงินและไม่ส่งคำร้องไปติดต่อสถานีแทนผู้ใช้

## แหล่งข้อมูลทางการที่ตรวจสอบ

- [Thai PBS ชมสด](https://www.thaipbs.or.th/live) และ [ผังรายการ](https://www.thaipbs.or.th/program/schedules/online)
- [CH7ON / 7HD ชมสด](https://www.ch7.com/th/live/) และ [ผังรายการ](https://www.ch7.com/th/schedule/)
- [PPTV HD 36 ชมสดและรายการถัดไป](https://www.pptvhd36.com/live)
- [YouTube embedded player parameters](https://developers.google.com/youtube/player_parameters): รูปแบบ iframe, video ID, ขนาดเครื่องเล่น และตัวควบคุมมาตรฐาน
- [HLS.js](https://github.com/video-dev/hls.js): HLS ผ่าน MediaSource, native HLS fallback, codec support และ CORS ของทุกทรัพยากร

ไม่ได้พบหรือยืนยันช่องทางสาธารณะที่อนุญาตให้นำสัญญาณของทุกสถานีมาเผยแพร่ซ้ำ จึงใช้ลิงก์ทางการเป็นค่าเริ่มต้น และเปิดสัญญาณในแอปเฉพาะเมื่อผู้ให้บริการส่งข้อมูลเข้ากระบวนการตรวจสอบ

## การตรวจสอบ

`npm run check`, `npm test`, `node test/social-tv-browser.js`, `node test/social-redesign-browser.js`, `node test/social-watch-browser.js`; การทดสอบ PostgreSQL เพิ่ม suite `social-tv` ใน `test/social-postgres.js` และการตรวจ deployment ตรวจไฟล์ player/CSP กับ API ที่ต้องล็อกอินด้วย

ทดสอบ HLS ด้วย fixture VP9/fMP4 เพราะ Chromium headless บาง build ไม่มี decoder H.264; ต้องทดสอบ codec/สิทธิ์/CORS ของสัญญาณสถานีจริงก่อนอนุมัติช่อง บราวเซอร์ที่เล่นไม่ได้จะแสดงสาเหตุที่เป็นไปได้และผู้ชมเปิดต้นทางได้
