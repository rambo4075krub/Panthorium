# แผนคลาวด์ที่ Panthorium ดูแลเอง

## คำตอบสั้น ๆ

บริการข้อมูลของ Panthorium ไม่จำเป็นต้องใช้ Google Cloud เจ้าของสามารถให้บริการจากเซิร์ฟเวอร์ที่ควบคุมเองได้ เช่น เครื่องเซิร์ฟเวอร์ของตนหรือเซิร์ฟเวอร์เช่าที่ตนดูแล โดยเปิดใช้ผ่านโดเมนและ HTTPS จากทั่วโลก

Google Play เป็นคนละส่วน: ใช้จัดการการซื้อ/ต่ออายุแพ็กเกจในแอป Android ได้ แต่ไม่ได้บังคับว่าฐานข้อมูลหรือไฟล์ของ Panthorium ต้องอยู่บน Google Cloud

## สถานะของโค้ดปัจจุบัน

- staging ในตอนนี้ยังใช้ Google Cloud Run, Cloud SQL และ Artifact Registry ตาม `.github/workflows/deploy-staging.yml`; ค่า AI ของ staging ยังเลือก Vertex ด้วย
- Notes เรียก API ที่จัดข้อมูลตามบัญชีและใช้ PostgreSQL ผ่าน `DATABASE_URL` โค้ดฐานข้อมูลส่วนนี้จึงไม่ผูกกับ Cloud SQL โดยตรง แต่ฐาน staging ที่ใช้อยู่ยังเป็นของ Google Cloud
- Files ถูกซ่อนชั่วคราวเพราะยังไม่มีบริการอัปโหลด/ดาวน์โหลดไฟล์บนเซิร์ฟเวอร์ นี่เป็นข้อจำกัดระหว่างพัฒนา ไม่ใช่ทิศทางผลิตภัณฑ์
- ปฏิทิน เตือนยา เตือนนัด และพื้นที่ไฟล์/รูป/วิดีโอ ยังต้องพัฒนาบริการ API และข้อมูลบนเซิร์ฟเวอร์เพิ่มก่อนเปิดใช้จริง

ดังนั้นตอนนี้ยังพูดไม่ได้ว่าระบบย้ายออกจาก Google Cloud แล้ว หรือมี private cloud พร้อมใช้งาน

## โครงสร้างเป้าหมาย

1. **แอปและ Panthorium Browser** เชื่อมต่อโดเมนของ Panthorium ผ่าน HTTPS
2. **API บนเซิร์ฟเวอร์ที่คุณควบคุม** ตรวจ session และระบุผู้ใช้จากข้อมูลยืนยันตัวตนฝั่งเซิร์ฟเวอร์ การเรียก API จะไม่เชื่อ `user_id` ที่แอปส่งมาเอง
3. **PostgreSQL ส่วนตัว** เก็บโน้ต ปฏิทิน งาน นัด ยา การตั้งค่า และ metadata โดยทุกแถวผูกกับบัญชีผู้ใช้
4. **ที่เก็บไฟล์ส่วนตัว** เก็บเนื้อหาไฟล์ รูป วิดีโอ และสื่อ แต่ละรายการมีเจ้าของและโควตา ตรวจสิทธิ์ทุกครั้งก่อนอ่าน ดาวน์โหลด แก้ไข หรือลบ ห้ามเปิด bucket หรือโฟลเดอร์เป็นสาธารณะ
5. **บริการชำระเงิน** ส่งสถานะการสมัครสมาชิกกลับมายัง API เพื่อกำหนดโควตาของบัญชี หลัง API ตรวจสอบรายการซื้อแล้วเท่านั้น
6. **การแจ้งเตือนบนโทรศัพท์** ข้อมูลนัด/ยาอยู่บนเซิร์ฟเวอร์เป็นหลัก แต่ Android ต้องได้รับการตั้งเวลาแจ้งเตือนผ่านระบบปฏิบัติการเพื่อให้เตือนได้ขณะไม่ได้เปิดแอป

การใช้เซิร์ฟเวอร์ของ Panthorium ไม่ได้แปลว่าโมเดล AI ทำงานบนเครื่องนั้นด้วย ปัจจุบัน staging ตั้งค่า Vertex หากต้องการให้บทสนทนาและเสียงไม่ส่งไปยังผู้ให้บริการ AI ภายนอก ต้องเพิ่มและดูแลโมเดล AI ที่โฮสต์เองแยกจาก API, ฐานข้อมูล และที่เก็บไฟล์

## ลำดับย้ายไปเซิร์ฟเวอร์ของคุณ

1. กำหนดเครื่อง/ผู้ให้บริการที่คุณควบคุม, ระบบปฏิบัติการ, พื้นที่ดิสก์, โดเมน และวิธีสำรองข้อมูล
2. เตรียม staging บนสภาพแวดล้อมนั้นก่อน ตั้ง HTTPS, PostgreSQL, secrets, firewall, monitoring และทดสอบกู้คืน backup
3. ปรับการตั้งค่า deploy ให้ชี้ API ไปยัง staging ของคุณ โดยไม่เปลี่ยน `main` และไม่ย้าย production ก่อนทดสอบ
4. ทำบริการ Files บนเซิร์ฟเวอร์ รวมโควตา การอัปโหลด/ดาวน์โหลดแบบยืนยันบัญชี การลบ/ส่งออกข้อมูล และการสแกนไฟล์ตามความเหมาะสม แล้วจึงเปิด Files UI
5. ย้าย Notes และข้อมูลบัญชีที่มีอยู่ด้วยขั้นตอนตรวจจำนวน/เจ้าของข้อมูลก่อนและหลังย้าย โดยรักษา ID บัญชีเดิม
6. พัฒนาปฏิทิน งาน เตือนยา และเตือนนัดให้ใช้ API และฐานข้อมูลบัญชีเดียวกัน; อุปกรณ์เป็นผู้แสดงผล/แจ้งเตือน ไม่ใช่แหล่งข้อมูลหลัก
7. เพิ่ม Play Billing และให้ backend ตรวจ purchase token กับ Google Play ก่อนเพิ่มสิทธิ์หรือโควตา
8. ทดสอบบัญชีแยกจากกันบนเว็บทั่วไปและ Panthorium Browser ทั้ง Admin/Guest และทดสอบบัญชีเดียวกันบนโทรศัพท์กับแท็บเล็ต ก่อนค่อยพิจารณา merge `main`

## ค่าใช้จ่ายและการเติบโต

รายได้ค่าพื้นที่ควรผูกกับโควตาที่วัดได้ เช่น GB ต่อบัญชี แทนการให้พื้นที่ไม่จำกัด ต้นทุนของคลาวด์ที่คุณดูแลเองมาจากเครื่อง/ดิสก์ เครือข่ายสำรองข้อมูล การรับส่งไฟล์ การดูแลระบบ และค่า AI หากยังเรียกโมเดลภายนอก ต้องวัดต้นทุนจริงก่อนตั้งราคา

เป้าหมายผู้ใช้ 10 ล้านคนต้องวางแผน capacity, การกระจายโหลด, redundancy, backup/restore, monitoring และทดสอบ load แยกต่างหาก เซิร์ฟเวอร์เครื่องเดียวเหมาะเพียงช่วงเริ่มต้นและทดสอบ ไม่ใช่หลักฐานว่ารองรับ 10 ล้านบัญชีได้

## ขอบเขตของ PR นี้

PR นี้เตรียมการแยกข้อมูลตามบัญชีและระบุทิศทาง self-hosted เท่านั้น ยังไม่ได้ตั้งเครื่อง/โดเมนของคุณ ยังไม่ได้ย้ายฐานข้อมูลออกจาก Google Cloud และยังไม่ได้เปิดระบบ Files หรือระบบชำระเงิน
