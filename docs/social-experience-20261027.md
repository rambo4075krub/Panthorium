# Social Media experience update

Search collapses into an accessible magnifier in all eleven content sections. The search submit button is inside the field. Attachments use a plus menu, an explicit Cloud Files picker, and a native upload picker with confirmation before any upload. Profile defaults to the current account's posts, newest first, with settings in a separate action.

Short and Watch use muted viewport playback and a full-viewport player with audio, bidirectional swipe/wheel history, play/pause/time/seek, two-line expandable descriptions, author avatar, share/comments/like, downloads and reporting. Single tap toggles the overlay; double tap sets a like without toggling it off. Only an access-checked current page is ranked, using follows, friendships and likes. Short publication probes the actual uploaded video on the server and rejects unreadable, multi-file and over-60-second submissions. Provider restrictions and browser autoplay restrictions still apply to externally hosted media; downloads are offered for attached files and provider links remain available.

Post-tab badges count new posts from followed accounts or accepted friends. Likes/comments/shares go to the Social bell. Moderation and commerce events remain in its separate additional-activity section. Chat/Community keep per-conversation badges; message read receipts still require visible messages. The bell read operation acknowledges only the account's accessible notifications created before opening. Every notification click rechecks original post permissions. Share notifications record successful user-triggered share/copy operations, not third-party engagement. The first profile image is an author avatar visible only to viewers authorized to read a post; private profile biographies and Connect aliases remain separate. Privacy notice 3.5 describes avatar display and automatic external-player requests.

Live now acquires camera/microphone permission before creating the room, plays the local preview, surfaces startup failures, and ends failed sessions. The existing eight-viewer capacity remains. Local authenticated Chromium video/audio and host-end teardown pass. Production has no SOCIAL_TURN_URLS or SOCIAL_TURN_SECRET; direct WebRTC can fail across NAT/firewalls. Provisioning a minimal isolated relay without a VM service account was blocked by the Google Cloud project policy constraints/compute.vmExternalIpAccess. No exception was applied. The temporary reserved address, firewall rules and isolated network were removed after the failed attempt. scripts/social contains the reviewed no-cloud-identity provisioning/configuration procedure, which requires an explicitly approved network-policy path before use. Never log the shared TURN secret. It must be held in Secret Manager and delivered to the private VM configuration through authenticated IAP SSH; clients receive only expiring HMAC credentials.

Validation: npm run check; npm test; Social RTC, messages, groups, notifications, redesign, Watch and TV real-browser tests; new social-experience API and browser acceptance tests. Provider fixtures verify embedding/lifecycle and direct HLS/video decoding, not whether a third-party TV provider honors autoplay on every device.

TrueID embeds require `autoplay=true` (the numeric value `1` is ignored). Real Microsoft Edge checks of Thai PBS, Channel 3 HD and Channel 7 HD verified advancing decoded frames with muted automatic playback. Other providers and devices retain their own autoplay policies.
