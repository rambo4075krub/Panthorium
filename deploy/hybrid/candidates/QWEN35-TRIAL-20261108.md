## Resource results

Q4_K_M (5,680,522,464 bytes) did not have sufficient headroom under the trial
budget. Metadata-only estimates at context 2048, batch 128, microbatch 64,
F16 KV cache:

| GPU layers | Device MiB (model + context + compute) | Host MiB |
| --- | ---: | ---: |
| 18 | 3081 | 2507 |
| 20 | 3332 | 2255 |
| 22 | 3592 | 1995 |

Q3_K_S (4,316,865,760 bytes) was tried separately. Default memory mapping caused
a transient whole-system RAM peak of 91.96%; the guard stopped the load before
any question ran. This demonstrates that projected steady-state memory alone
does not bound startup peaks. It is not a successful test.

The next attempt used `--load-mode none`, 22 GPU layers, context 2048, four CPU
threads, one slot, no web UI or built-in agent, a temporary API key, and loopback
port 18090. RAM was checked every 50 ms, with slower GPU/broker/CPU checks.
Limits applied only to the trial: RAM 82%, at least 2.5 GiB available, GPU memory
80%, GPU temperature below 82 C, 480 seconds maximum. Main-system limits remained
65% RAM and 60% VRAM. These are sampled stop thresholds, not OS hard guarantees.

This run completed seven synthetic requests. Peak whole-system RAM was 80.67%,
GPU memory 71.66%. Measured generation speed ranged from 8.97 to 11.59 tokens/s.
All candidate processes stopped and the temporary API key was removed afterward.
